**Source:** `reviews/arch-review-2026-11-09.md` (ARCH). Monday checked the code at `349d07d` and the line numbers below match it.
**Rules:** Read `CLAUDE.md` first. Use one commit per item, each with its tests. **Don't push** (the owner's call). Don't touch the Pi, Peak's Ollama or the models. Run `PEAK_SIM=1` only.
**Verify after each item:** `cd mind && npm test`, and `cd node && python3 -m pytest -q` (or the repo's usual runner).

The idea behind all of it: **a stop is the one command that is always safe.** Anything that can delay it, drop it or narrow it is a bug. Anything that can move a servo without a stop path being alive is also a bug.

## 1. One stop matcher, in two strengths (B2 + S3, mind)

**Problem:** stop detection lives in two places. One is `senses/heardFilter.js:29 isStop`, which hearing uses to let a stop through half-duplex. The other is `orchestrator/fastlane.js:45`, which has seven exact phrases. They drift, and both are too narrow.

**Watch out:** ARCH's S3 rule ("first or last word is stop") clashes with `senses/halfDuplex.test.js:57`, which expects "Stop the car." and "Bro stop being so dramatic." **not** to be stops. That test is there for a reason. Hearing's half-duplex bypass lets a stop through *over Rho's own voice*. A broad rule there means any Rho line containing "stop" would stop Rho itself.

**Fix: two strengths, one module** (`mind/lib/stop.js`, imported by both):
- `isStrictStop(text)` is today's `isStop`, unchanged. It's used only for the half-duplex bypass (echo risk), so the existing tests still pass.
- `isStopIntent(text)` is broad. Use it after the echo filter, in the fast lane. Normalize the text, then treat it as a stop when either:
  - the first or last word is `stop|freeze|halt|enough`;
  - or it contains `stop` and is at most 4 words.

  Keep the fast lane's NEGATION exemption as it is: "don't stop" isn't a stop.
- In `fastlane.js` `match()`, check `isStopIntent` **before** the template lookup and return the stop hit.

**Tests:**
- "wait stop", "stop moving", "no no stop", "stop it now Rho" and "ok enough" are stops. "don't stop" isn't.
- The existing `halfDuplex.test.js:55-57` still passes, unchanged.

## 2. Check for a stop before the age check (B2, mind)

- **`orchestrator/index.js:98-101`:** swap the order. Run `lane.match` first. If the hit is a stop, call `fast()` regardless of age. Only then call `stale()` → `vetoStale`.
- **`think()` at `:179`:** the stale check never sees a stop now, because stops don't go to the brain. Add an assert-style comment anyway, so a refactor can't break it.
- **Cap:** treat a stop older than 60 s as noise (log it, don't publish). It's an idempotent cancel either way, but a minute-old stop arriving after a restart shouldn't kill a fresh move.

**Test (new `index`-level test, or factor the routing out into `route(event, at, now)` and test that):** a `heard: "stop"` with `at` 30 s old still publishes `{"stop":true}`. A non-stop 30 s old is vetoed.

## 3. Hearing: stops jump the queue (B3, mind)

**Problem:** `senses/hearing.js:72-74` keeps one waiting slot, and the newest utterance wins. Rho's echo can overwrite a waiting "stop" before whisper ever hears it.

**Smarter than a plain FIFO:** stops are **short**. A spoken stop is under about 1.2 s of audio, and echo of a Rho line is usually long. So:
- Replace `waiting` with a small queue, `MAX_WAITING = 3`.
- **Order:** take short utterances (≤ 1.5 s of PCM) first, then FIFO. A stop never waits behind two long echo segments.
- **When it's full:** drop the **longest** waiting item, not the newest or the oldest. Never drop a short one while a long one is queued.
- Don't drop anything by age before it's transcribed. The age rule applies after transcription and after the stop check, as ARCH says.
- Log every drop with its length, so `npm run perf` or the log shows whether the queue ever fills.

**Test:** unit-test the queue (a pure function: `push(q, item) → q`, `next(q) → item`). In a stream of 5 long items and 1 short item arriving while busy, the short one is next, and nothing short is evicted.
**Live:** replay the 144-mix harness, then do a 60 s barge-in window: the owner says "stop" over a long Rho line, 5 times out of 5.

## 5. Stop holds, and release is its own command (B5, node + contract)

**Why first:** do this **before real servos**. Today `stop` → `servos.release()` (`servod.py:422-426`), so a raised arm drops. The dead-man path already holds, so the two stops disagree.

**Fix:**
- `stop`: `cancel_motion()`, keep the servos powered where they are, eyes `release`. Put this in **one** function shared with the dead-man `hold()`, so they can't drift apart again.
- New `{"release": true}` → `cancel_motion()` + `servos.release()`. Add it to:
  - `contracts/cmd.schema.json` (a new `oneOf` arm);
  - `cmdcheck.kind` (checked after `stop`, never refused);
  - `run_cmd`.
- Nothing in the mind sends `release` yet. That's deliberate: it's an owner-only tool for now (`mosquitto_pub`).
- Update `docs/decisions.md` (Stage B note) and the stop rows in `CLAUDE.md`.

**Tests:** `test_cmdcheck.py` accepts release. In sim, a servo test shows stop keeps `pos` and release prints the release line.

## 7. A heartbeat beats a retained "online" (S2, mind + node)

**Fix:** a Last Will can't catch a hung mind, or a broker that restarted with a persisted "online". So:
- **Mind:** publish `peak/mind/mind/beat` = `{"at": ms}` every 2 s. Use QoS 0, **not retained**.
- **servod `DeadMan`:**
  - add `on_beat(now)` and `tick(now)`;
  - `alive` also requires a beat within 6 s, **once a first beat has been seen**, so an old mind without beats still works during rollout;
  - check `tick()` in the sense loop (every 5 s), or better on a 1 s timer;
  - the dead-man gate (item 4) then blocks new moves when the beats stop.
- **ACL:** `mech` needs `topic read peak/mind/mind/beat`. `mind` already has `peak/#`.
- **Belt and braces:** `health` publishes a retained `offline` to `peak/mind/mind/status` at start when the mind's process isn't running (ARCH's option a). It's cheap, so do both.

**Tests:** `test_deadman.py`: beats seen, then 7 s of silence → not alive. No beat ever → alive (rollout). A beat returns → alive again.
